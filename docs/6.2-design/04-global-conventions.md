## 3. 角色标签显示规则

- 标签位于头像下方，只显示文字与边框，不使用头像框。
- 一个账号只有一个当前系统角色；在校学生的物品参与者身份不是额外系统角色。
- 校级管理员登录后显示“校级管理员”标签，并进入本校管理范围；不能跨校操作。
- 若未来支持一个账号多重职责，页面可以显示多个标签，但首版数据库仍按单一主角色设计。

## 4. 物品状态

| 代码 | 中文 | 含义 |
|---|---|---|
| `active` | 可申请 | 当前没有活动申请，可以浏览和申请 |
| `reserved` | 已被申请 | 存在待处理或已接受、尚未开始履约的申请 |
| `in_progress` | 流转中 | 已交接，借用中或等待回收验收 |
| `completed` | 已完成 | 当前业务已结束 |
| `off_shelf` | 已下架 | 所有者主动下架 |
| `on_hold` | 异常冻结 | 争议或管理员处理中 |

允许转换：

| 起点 | 事件 | 终点 | 责任角色 |
|---|---|---|---|
| `active` | 创建活动申请 | `reserved` | 在校学生 |
| `reserved` | 拒绝/取消/模拟支付失败 | `active` | 所有者、申请人、系统 |
| `reserved` | 交接成功，开始借用或等待回收验收 | `in_progress` | 接收方、公益管理员 |
| `reserved` | 出售/赠送交接成功 | `completed` | 接收方 |
| `in_progress` | 借用归还确认或回收验收通过 | `completed` | 所有者、公益管理员 |
| 任意有活动业务状态 | 发起争议或管理员冻结 | `on_hold` | 参与人、平台管理员 |
| `on_hold` | 争议关闭且业务完成 | `completed` | 平台管理员 |
| `completed` | 所有者重新上架，回收模式除外 | `active` | 所有者 |
| `active` | 所有者下架 | `off_shelf` | 所有者 |
| `off_shelf` | 所有者重新上架 | `active` | 所有者 |

## 5. 流转申请状态

| 代码 | 中文 | 适用模式 |
|---|---|---|
| `pending` | 待处理 | 四种模式 |
| `accepted` | 已接受 | 四种模式 |
| `payment_pending` | 待模拟支付 | 出售 |
| `handover_pending` | 待交接 | 四种模式 |
| `in_progress` | 借用中 | 借用 |
| `return_pending` | 待归还确认 | 借用 |
| `inspection_pending` | 待回收验收 | 回收 |
| `completed` | 已完成 | 四种模式 |
| `rejected` | 已拒绝 | 四种模式 |
| `cancelled` | 已取消 | 四种模式 |
| `disputed` | 争议中 | 四种模式 |

### 5.1 通用允许转换

| 当前状态 | 操作 | 下一状态 | 操作者 |
|---|---|---|---|
| `pending` | 接受 | `accepted` | 所有者或回收站点 |
| `pending` | 拒绝 | `rejected` | 所有者或回收站点 |
| `pending` | 取消 | `cancelled` | 申请人 |
| `accepted` | 准备交接 | `handover_pending` | 服务端 |
| `accepted`、`payment_pending`、`handover_pending` | 交接前取消 | `cancelled` | 约定双方 |
| `handover_pending` | 业务结束或进入履约 | 按模式确定 | 接收方/站点 |
| `completed` | 发起争议 | `disputed` | 参与人，条件允许时 |

### 5.2 分模式路径

| 模式 | 正常主链 | 专属异常 |
|---|---|---|
| 借用 | `pending → accepted → handover_pending → in_progress → return_pending → completed` | 逾期继续显示；损坏可转 `disputed` |
| 出售 | `pending → accepted → payment_pending → handover_pending → completed` | 模拟支付失败/取消回 `accepted` 或 `cancelled` |
| 赠送 | `pending → accepted → handover_pending → completed` | 交接前可取消，交接后走争议 |
| 回收 | `pending → accepted → handover_pending → inspection_pending → completed` | 验收拒绝回 `rejected` 并保留原因 |

## 6. 公益状态

### 6.1 公益项目

| 代码 | 中文 | 允许操作 |
|---|---|---|
| `draft` | 草稿 | 管理员编辑需求 |
| `active` | 募集中 | 用户可查看和捐赠 |
| `completed` | 已完成 | 只读，可创建回执 |
| `cancelled` | 已取消 | 只读，不接收新捐赠 |

允许转换：`draft → active`、`active → completed`、`active → cancelled`。达到目标或超过截止时间后，service 停止创建新捐赠；管理员确认完成。

### 6.2 捐赠核验

| 代码 | 中文 | 计数规则 |
|---|---|---|
| `pending` | 待核验 | 不计入已接收数量 |
| `received` | 已接收 | 按核验数量计入，不得超募 |
| `rejected` | 已拒绝 | 不计入，保留原因 |
| `cancelled` | 已取消 | 不计入 |

### 6.3 回执

| 代码 | 中文 | 可见性 |
|---|---|---|
| `draft` | 草稿 | 公益管理员和平台管理员 |
| `published` | 已公示 | 本校用户可见 |

## 9. 中文状态与反馈

- 状态名称只能使用本文档表中的中文，不在页面中另造“进行中”“处理中”等同义词替代明确状态。
- 出错页面必须给出：当前对象、失败原因、可执行的下一步。
- 成功操作使用页面提示，不依赖浏览器弹窗。
- 危险操作使用二次确认，并说明不会删除历史记录。

## 10. 统一错误分类

| 类型 | 页面行为 | 示例 |
|---|---|---|
| 未登录 | 跳转登录并保留目标页 | 访问我的申请 |
| 无角色权限 | 返回 403 页面 | 学生访问管理台 |
| 跨校对象 | 返回 404 或无权限，不泄露对象存在与否 | 访问外校物品 |
| 状态冲突 | 返回对象详情并解释当前状态 | 第二人申请已被占用的物品 |
| 输入错误 | 表单原位显示字段错误 | 学号格式错误、日期倒置 |
| 外部存储失败 | 保留已填表单，允许重试 | R2 上传失败 |
| 未处理异常 | 显示请求标识，不显示堆栈和敏感信息 | 数据库暂时不可用 |

## 11. 日期与金额

- 日期输入和展示使用 `Asia/Shanghai`，数据库存 UTC。
- 借用日期按自然日处理；当天开始、当天结束允许。
- 金额输入到分，数据库中只保存整数分；页面显示 `¥xx.xx`。
- 模拟支付明确标注“教学模拟，不产生真实扣款”。
