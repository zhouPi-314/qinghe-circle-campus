# 青禾流转 6.1 同类产品功能拆解

| 项目 | 内容 |
|---|---|
| 文档版本 | 1.0 |
| 日期 | 2026-11-19 |
| 分析人 | 项目维护者 |
| 用途 | 识别常见产品模式，经人工删减后形成本项目需求 |

> 本文件只吸收公开产品中的业务模式，不复制页面、文案、代码或数据库。市场热度不作为需求保留依据。

## 1. 参考产品与模式

| 产品/项目 | 参考的业务模式 | 与本项目的关系 |
|---|---|---|
| 美团/京东等外卖应用 | 多角色、商品浏览、订单、状态流转、履约、售后 | 参考订单和履约闭环，不采用商家入驻、骑手、地图和真实支付 |
| [Olio](https://olioapp.com/) | 校园/社区闲置与免费分享 | 参考物品发布、图片、校内交接和分享；增加正式借用、归还和回收 |
| [Freecycle](https://www.freecycle.org/) | 社区免费赠送 | 参考免费赠送流程；简化社区审批与邮件组模式 |
| [Circulate](https://github.com/chicago-tool-library/circulate) | 借阅图书馆、成员、借期和归还 | 参考借用、到期和交接责任；不实现复杂会员收费 |
| [Snipe-IT](https://github.com/grokability/snipe-it) | 资产状态、领用、历史和审计 | 参考状态历史和可追溯性；不实现企业资产采购和折旧 |
| [Library of Things](https://www.reusealliance.org/library-of-things) | 低频物品共享、可用状态和借还规则 | 参考共享模式；增加校园范围和公益分支 |

## 2. 外卖应用功能拆解

| 功能 | 是否借鉴 | 本项目处理 |
|---|---|---|
| 店铺列表与菜单 | 部分 | 物品列表、分类和详情 |
| 购物车 | 否 | 校园单件流转不采用多商品购物车 |
| 下单 | 是 | 借用、购买、领取和回收申请 |
| 支付 | 部分 | 二手交易保留模拟支付状态 |
| 商家接单 | 是 | 所有者确认申请 |
| 骑手配送 | 否 | 改为校内自提和交接码 |
| 订单状态 | 是 | 借还、交易、赠送和回收分别建模 |
| 售后/争议 | 是 | 保留争议和管理员处理 |
| 评价 | 延后 | 首版不阻塞核心闭环 |
| 地图和实时位置 | 否 | 使用校区、建筑和线下交接 |

## 3. Olio / Freecycle 功能拆解

| 功能 | 是否借鉴 | 本项目处理 |
|---|---|---|
| 发布免费物品 | 是 | 免费赠送模式 |
| 物品图片与描述 | 是 | 物品主信息和 R2 图片 |
| 按地点发现物品 | 是 | 本校、同校跨校区筛选 |
| 私信沟通 | 否 | 首版使用申请留言和站内通知，不做实时聊天 |
| 用户信任/评分 | 延后 | 依靠高校范围、名单核验、状态历史和争议处理 |
| 社区审核 | 简化 | 平台管理员下架和管理争议 |

## 4. Library of Things / Circulate 功能拆解

| 功能 | 是否借鉴 | 本项目处理 |
|---|---|---|
| 可借物品目录 | 是 | 物品浏览和搜索 |
| 可借时间与借期 | 是 | 借用起止日期和冲突校验 |
| 提交借用申请 | 是 | 所有者和借用人双向确认 |
| 交接记录 | 是 | 一次性交接码和状态历史 |
| 到期与逾期 | 是 | 页面动态显示逾期 |
| 归还检查 | 是 | 归还说明、可选图片和争议 |
| 会员费与押金 | 否 | 不接真实支付 |
| 复杂预约日历 | 否 | 首版使用起止日期，不开发可视化排班 |

## 5. Snipe-IT 功能拆解

| 功能 | 是否借鉴 | 本项目处理 |
|---|---|---|
| 物品状态 | 是 | 可申请、处理中、待交接、业务中、已完成、下架 |
| 领用/责任人 | 是 | 流转申请、交接双方和操作历史 |
| 操作历史 | 是 | 状态历史和管理员审计 |
| 资产采购与折旧 | 否 | 与校园闲置循环无关 |
| 企业级权限组 | 简化 | 三类角色和高校范围 |

## 6. 综合后的差异化方向

本项目不是外卖，也不是普通二手商城。核心差异是：

1. 一件物品可以按明确模式完成借用、出售、赠送或回收。
2. 同一物品不允许并发多种流转。
3. 交接码证明校园线下履约。
4. 多高校逻辑隔离，同校跨校区允许。
5. 公益实物、募集进度和回执形成可查询闭环。
6. 所有高风险外部能力采用模拟或删除。

## 7. 删减结论

保留并重组：

- 物品发布、浏览、图片和校内交接；
- 订单状态思路；
- 借阅期限、归还和逾期；
- 状态历史和审计；
- 免费物品与校内分享；
- 公益物资募集。

简化：

- 二手支付改为模拟；
- 私信改为申请留言和站内通知；
- 评价和信誉延后；
- 复杂会员和押金删除；
- 管理员权限简化为三类角色。

删除：

- 地图、骑手和物流；
- 购物车和多商品批量订单；
- 实时聊天；
- 推荐算法；
- 真实支付与真实公益资金。
