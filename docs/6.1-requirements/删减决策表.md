## 1. 决策原则

- P0 功能必须保证完整闭环。
- P1 功能在核心闭环稳定后加入。
- P2 功能不进入首版代码。
- 真实支付、身份接口、公开募捐和物流不进入项目；真实短信只用于学生注册验证码。
- 同一物品同一时间只允许一种进行中的流转。
- 多高校只做逻辑隔离，不接真实高校认证。

## 3. 首版模块归纳

| 模块 | 主要需求 |
|---|---|
| 账号与权限 | 注册、登录、名单核验、验证码、角色和资料 |
| 高校与学生数据 | 高校、校区、学生名单和管理范围 |
| 物品与媒体 | 发布、编辑、分类、搜索、图片和上下架 |

| 公益首版 | 项目、目标进度、实物捐赠、核验和回执 |

## 4. 最终删减结论

- 保留：账号与组织、物品、四类流转、交接与异常、公益三项。
- 简化：短信、支付、通知、环保贡献、搜索、统计、审计。
- 延后：公益义卖、公益金额认领、收藏、评价体系、CSV 导出、学校管理员。
- 删除：真实支付、真实身份接口、聊天、地图物流、推荐算法、积分商城。
- G5：校级管理员、注册验证码、阿里云短信认证和运维安全中心已纳入当前实现；Cloudflare WAF 暂缓，不阻断课程交付。
