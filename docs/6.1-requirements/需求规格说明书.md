## 1. 目的

本文档冻结首版业务范围、角色、规则、主流程、异常和验收标准，作为 6.2 设计的唯一需求输入。

## 2. 项目范围

### 2.1 纳入首版

- 多高校逻辑隔离，支持一个或多个校区。
- 学生名单核验注册、密码登录、模拟验证码登录。
- 在校学生、公益管理员（回收）、平台管理员；校级管理员作为预留登录身份，不开放管理功能。
- 物品发布、搜索、浏览、图片和状态展示。
- 共享借还、二手交易、免费赠送、绿色回收。
- 一次性交接码、取消、逾期、归还和争议。
- 公益实物捐赠、公益项目目标与募集进度、公益回执公示。
- 基础通知、管理审核、状态历史、统计和审计记录。
- 基础响应式 Web 页面。

### 2.2 不纳入首版

- 真实支付、退款、资金托管。
- 真实短信、邮件验证码、实名认证和高校官方接口。
- 公益义卖、公益金、微心愿金额认领。
- 实时聊天、用户动态、关注和推荐算法。
- 地图、骑手、物流和快递面单。
- 积分商城和优惠券。
- 移动 App 和微信小程序。

## 3. 角色和权限

| 角色 | 权限范围 | 主要能力 |
|---|---|---|
| 在校学生 | 所属高校；同校跨校区可见 | 发布物品、申请借用/购买/领取/回收、归还、捐赠、查看记录、发起争议 |
| 公益管理员（回收） | 被分配高校和站点 | 处理回收、核验公益实物、更新募集和回执 |
| 平台管理员 | 全局 | 维护高校/校区/站点、导入名单、创建管理账号、审核、仲裁和统计 |
| 校级管理员（预留） | 所属高校，管理功能暂未开放 | 首版仅预留账号和登录入口 |

在校学生、公益管理员（回收）、平台管理员在头像下分别显示蓝、橙黄、红色文字标签边框。标签不是头像框。校级管理员为预留身份，首版不进入业务页面。

## 4. 总体业务规则

### 4.1 高校与校区

- BR-001：所有用户、物品、流转、公益项目和回执必须属于一个高校。
- BR-002：用户只能访问本校数据，跨学校访问返回拒绝提示。
- BR-003：同校不同校区之间允许流转和交接。
- BR-004：单校区高校按一个校区运行，不要求额外配置多个校区。

### 4.2 账号

- BR-005：学生必须在管理员已导入的本校学生名单中，且学号与手机号匹配，才能注册。
- BR-006：学生姓名、学院、专业、年级、班级和校区从名单带入，用户可修改昵称与头像，不能自行修改学号、手机号和归属高校。
- BR-007：公益管理员（回收）和校级管理员账号只能由平台管理员导入或预置；平台管理员账号由系统预设。
- BR-008：平台管理员首版只预置 1 个账号，不设总数上限；其他管理员账号不开放自主注册。
- BR-009：手机验证码为服务器端模拟校验，60 秒内有效；页面不得由前端自行决定验证码正确性。
- BR-010：测试验证码只在开发/演示环境显示，生产环境提示联系管理员获取演示支持。

### 4.3 物品和流转互斥

- BR-011：物品当前流转方式只能是借用、出售、赠送或回收之一。
- BR-012：同一物品同一时间只能存在一个进行中的流转业务。
- BR-013：物品存在进行中业务时不能编辑关键字段、下架、切换流转方式或接受第二份申请。
- BR-014：申请被拒绝、取消或模拟支付失败后，物品恢复为可申请状态。
- BR-015：完成业务后物品不自动重新发布，所有者可以选择重新上架；回收完成后不可重新上架。

### 4.4 交接

- BR-016：申请经有权一方确认后才可生成交接码。
- BR-017：交接码为 6 位一次性数字码，10 分钟有效；重新生成后旧码失效。
- BR-018：交接码由交付方生成，接收方输入；成功一次后立即失效。
- BR-019：交接双方必须属于同一高校；跨校交接禁止。
- BR-020：借用物品取件成功后进入借用中；出售和赠送成功交接后完成；回收交接后还需站点验收。

### 4.5 借用

- BR-021：借用必须有开始日期和预计归还日期，归还日期不得早于开始日期。
- BR-022：出借人批准时需校验相同物品借用时间段不重叠。
- BR-023：借用人提交归还后，出借人确认完成；损坏或描述不符时转争议。
- BR-024：超过预计归还日期仍未归还时显示逾期；逾期由页面动态计算，不依赖定时任务。

### 4.6 二手与赠送

- BR-025：二手交易必须标明模拟价格，系统只记录模拟支付状态。
- BR-026：模拟支付失败、用户取消或卖家拒绝后，物品恢复可申请。
- BR-027：免费赠送不产生支付，发布者确认领用人并完成交接。
- BR-028：二手和赠送交接完成后不可普通取消，只能通过争议处理。

### 4.7 回收

- BR-029：用户提交回收时选择本校回收点和期望送达时段。
- BR-030：公益管理员（回收）可接受、拒绝或标记待送达。
- BR-031：用户送达后由站点验收；不符合回收条件时拒绝并记录原因。
- BR-032：验收完成后计入该用户的校园环保贡献数量；首版不做积分兑换。

### 4.8 公益

- BR-033：公益项目必须属于一个高校，包含目标物品、目标数量、截止时间、接收组织和公开说明；项目可用于展示书籍、文具等微心愿需求，但首版不做金额认领。
- BR-034：用户只能捐赠本校公益项目。
- BR-035：捐赠须经公益管理员（回收）核验后，数量才计入募集进度。
- BR-036：确认数量不得超过项目目标数量。
- BR-037：项目完成后不再接受新的有效捐赠申请。
- BR-038：回执必须包含物资种类、数量、发放/接收时间、接收组织和回执说明。
- BR-039：公开回执不得包含儿童姓名、联系方式、家庭地址、清晰人脸或其他可识别个人信息。
- BR-040：公益首版不接收真实资金，不展示真实募捐账户。

### 4.9 争议和管理

- BR-041：物品交接完成后出现损坏、描述不符或其他争议时，当事人可以提交说明和管理员处理申请。
- BR-042：管理员可查看状态历史、交接记录和双方说明，作出记录结论；首版不做真实赔付。
- BR-043：管理员可以下架违规物品；存在进行中业务时先进入异常处理状态，不能直接删除历史记录。

### 4.10 登录入口

- BR-044：登录必须先选择身份。在校学生随后选择学校和校区；公益管理员、平台管理员和校级管理员进入各自登录界面。
- BR-045：高校库首批录入四川省普通高等学校；单校区高校的校区选择显示学校全称。

## 5. 功能需求

### 5.1 高校和学生名单

| ID | 需求 | 验收标准 |
|---|---|---|
| FR-U01 | 平台预置高校和校区数据 | 可展示单校区和多校区高校 |
| FR-U02 | 平台管理员维护高校、校区和站点 | 新增数据可被用户和物品选择 |
| FR-U03 | 平台管理员上传 UTF-8 CSV 学生名单 | 显示导入成功、失败行和错误原因 |
| FR-U04 | 记录导入批次、操作人、时间和结果 | 管理员可查看历史导入记录 |

### 5.2 注册、登录与资料

| ID | 需求 | 验收标准 |
|---|---|---|
| FR-A01 | 仅在校学生使用学号 + 手机号 + 密码注册 | 匹配名单时成功；不匹配时拒绝 |
| FR-A02 | 注册格式和重复检查 | 空值、格式错误、重复账号有明确提示 |
| FR-A03 | 手机号错误提示 | 显示确认文案并提示联系辅导员 |
| FR-A04 | 先选身份，再进入对应登录界面 | 四类身份入口可区分；非学生账号无注册入口 |
| FR-A05 | 图片验证码 + 模拟手机验证码登录 | 先通过图片验证码，验证码 60 秒过期 |
| FR-A06 | 修改昵称和头像 | 修改后页面生效，头像可在 R2 公网读取 |
| FR-A07 | 三类首版业务角色标签 | 学生、公益管理员、平台管理员显示对应颜色；校级管理员预留不显示业务标签 |
| FR-A08 | 学生选择学校和校区后登录 | 登录账号必须属于所选学校；单校区显示学校全称 |

### 5.3 物品

| ID | 需求 | 验收标准 |
|---|---|---|
| FR-I01 | 发布物品 | 保存名称、分类、成色、描述、校区、流转方式；出售时含价格 |
| FR-I02 | 上传图片 | 最多 5 张；统一存储到 R2；单图不超过 3 MB |
| FR-I03 | 浏览和筛选本校物品 | 不显示其他学校物品；同校其他校区可见 |
| FR-I04 | 关键词、分类、模式和校区筛选 | 组合条件返回正确结果 |
| FR-I05 | 查看物品详情 | 展示状态、发布者、图片和允许操作 |
| FR-I06 | 编辑、下架、重新上架 | 只在无进行中业务时允许；管理员可强制下架并记录原因 |

### 5.4 共享借还

| ID | 需求 | 验收标准 |
|---|---|---|
| FR-B01 | 借用申请 | 输入起止日期和留言，提交给物品所有者 |
| FR-B02 | 接受或拒绝 | 所有者可处理；拒绝后可重新申请 |
| FR-B03 | 借期冲突校验 | 重叠的已批准借期不能再次批准 |
| FR-B04 | 取件交接 | 接收者输入有效交接码后进入借用中 |
| FR-B05 | 逾期显示 | 超过归还日期时列表和详情显示逾期 |
| FR-B06 | 提交归还 | 借用人填写归还说明，可选图片 |
| FR-B07 | 归还确认或争议 | 所有者确认完成或转入争议 |

### 5.5 二手交易

| ID | 需求 | 验收标准 |
|---|---|---|
| FR-S01 | 买家提交购买申请 | 显示标价和成色，卖家可接受/拒绝 |
| FR-S02 | 模拟支付 | 可产生成功、失败、取消状态；失败或取消解除占用 |
| FR-S03 | 成交交接 | 有效交接码完成后记录成交 |

### 5.6 赠送与回收

| ID | 需求 | 验收标准 |
|---|---|---|
| FR-G01 | 免费赠送申请 | 同一时间只保留一个有效申请 |
| FR-G02 | 赠送交接 | 有效交接码完成后进入已完成 |
| FR-R01 | 提交回收申请 | 选择本校站点和送达时段 |
| FR-R02 | 站点处理 | 接受、拒绝、待送达状态可转换 |
| FR-R03 | 完成回收 | 站点验收后计入环保贡献 |

### 5.7 交接、异常和通知

| ID | 需求 | 验收标准 |
|---|---|---|
| FR-H01 | 生成和验证一次性交接码 | 6 位、10 分钟有效、一次性、同校校验 |
| FR-H02 | 交接前取消 | 双方可在允许状态取消并写明原因 |
| FR-H03 | 状态历史 | 显示操作者、时间、旧状态和新状态 |
| FR-H04 | 发起争议 | 当事人填写原因并可上传可选证据 |
| FR-H05 | 管理员处理争议 | 记录结论并关闭或恢复业务 |
| FR-H06 | 站内通知 | 申请、确认、拒绝、交接、逾期和争议有站内通知记录 |

### 5.8 公益首版

| ID | 需求 | 验收标准 |
|---|---|---|
| FR-C01 | 创建公益项目 | 含高校、物品类别、目标数量、截止时间、接收组织 |
| FR-C02 | 提交书籍等实物捐赠 | 捐赠人、数量、说明、图片和站点可保存 |
| FR-C03 | 站点核验捐赠 | 核验后计入进度，拒绝时记录原因 |
| FR-C04 | 展示目标和募集进度 | 已接收、目标和剩余数量正确，不超募 |
| FR-C05 | 项目完成 | 达到目标或截止时间到期后停止接受新捐赠 |
| FR-C06 | 上传回执 | 登记物资、数量、时间、接收组织和说明 |
| FR-C07 | 回执公示 | 本校用户可查看已发布回执 |
| FR-C08 | 公益义卖 | 首版不显示入口，不创建占位功能 |

### 5.9 管理

| ID | 需求 | 验收标准 |
|---|---|---|
| FR-M01 | 平台管理员查看用户、物品和流转统计 | 统计只包含管理范围 |
| FR-M02 | 管理员下架违规内容 | 下架原因和操作时间可追踪 |
| FR-M03 | 公益管理员（回收）管理本站回收和公益 | 不能处理其他站点 |
| FR-M04 | 平台管理员审计关键操作 | 状态、审核、导入和争议记录可查询 |

## 6. 异常需求

| 场景 | 系统行为 |
|---|---|
| 未登录访问 | 跳转登录，登录后返回原目标页 |
| 跨学校访问 | 返回无权限页，不泄露对象详情 |
| 学号手机号不匹配 | 拒绝注册并提示联系辅导员 |
| 重复注册 | 拒绝并引导登录 |
| 物品已被其他人申请 | 禁止创建第二个进行中申请 |
| 交接码错误 | 提示错误，原状态不变 |
| 交接码过期或已用 | 提示重新生成或联系对方，不得复用 |
| 借用逾期 | 显示逾期状态，仍允许归还 |
| 归还物品异常 | 可转争议，保留证据和处理记录 |
| 模拟支付失败/取消 | 解除物品占用，不产生成交 |
| 回收站拒绝 | 记录原因，物品不再自动回到可申请状态，所有者可重新发布 |
| 公益超募 | 超出部分不得确认计入，提示管理员核验数量 |
| 图片失败 | 不允许发布时使用临时地址；图片上传失败要回滚或允许重新上传 |
| 管理员下架进行中物品 | 冻结新操作并进入异常处理，不清除历史 |

| ID | 需求 |
|---|---|
| NFR-01 | Web-only，桌面优先，手机浏览器可完成核心流程 |
| NFR-02 | 关键状态变更必须在服务端校验，不能依赖页面隐藏 |
| NFR-03 | 关键写操作使用事务，重复提交不得产生重复业务 |
| NFR-04 | 图片只允许 JPEG/PNG/WebP，单图不超过 3 MB，单物品最多 5 张 |
| NFR-05 | 日志和错误页不显示密码、验证码、手机号、连接串和密钥 |
| NFR-06 | 同一学校数据隔离，所有业务服务校验高校范围 |
| NFR-07 | 使用统一中文术语和统一角色标签 |
| NFR-08 | 文档和数据库结构可复现，种子数据可重新导入 |
| NFR-09 | 页面核心操作提供明确成功、失败和下一步提示 |
| NFR-10 | 公网版本在 Vercel、Neon 和 R2 上完成 smoke test |

## 8. 首版验收标准

1. 学生名单匹配注册成功，冒领和格式错误被拒绝。
2. 两种登录方式可用，验证码 60 秒后失效。
3. 三类业务角色权限和显示标签正确；管理员账号不能自主注册，校级管理员入口标记为预留。
4. 用户只能看到本校数据，同校跨校区流转正常。
5. 同一物品不能被两个进行中业务同时占用。
6. 借用、出售、赠送、回收均可完成至少一条正常闭环。
7. 取消、拒绝、逾期、归还、损坏和争议均有处理路径。
8. 公益项目可以完成“发布—实物捐赠—核验—进度—回执公示”。
9. 公益确认数量不会超过目标数量。
10. 图片成功上传至 R2 并可公网读取。
11. 从空数据库按 README 可启动并导入种子数据。
12. 公网部署后健康检查、登录、数据库和图片读取通过。

## 9. 需求优先级

- P0：不能缺失，否则业务不闭环或存在数据/安全风险。
- P1：首版应完成，但可以在核心闭环稳定后补齐展示和审计细节。
- P2：不进入首版代码，只保留在后续规划。

本需求文档全部首版条目视为 P0/P1，P2 内容见删减决策表。
