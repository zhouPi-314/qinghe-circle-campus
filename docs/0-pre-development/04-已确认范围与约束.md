## 3. 业务范围

### 3.1 物品流转

首版四类流转均要求完整可操作：

1. 共享借还。
2. 二手交易。
3. 免费赠送。
4. 绿色回收。

同一物品在同一时间只能存在一种进行中的流转业务。具体状态和互斥规则在 6.1、6.2 中定义。

### 3.2 公益首版

首版仅实现：

1. 书籍等实物的公益捐赠。
2. 公益项目目标与募集进度。
3. 物资接收后的回执公示。

公益义卖与使用虚拟公益金额认领微心愿保留在总体设计中，但不进入首版代码。

### 3.3 数据规模

- PPT 没有规定业务表总数，6.1 不预设固定表数。
- 最终表数由 6.2 概念数据模型、实体关系和业务职责确定。
- 预留学校、校区、学生名单导入批次、状态历史、操作审计、交接记录、公益回执等表。
- 不通过无业务意义地拆分数据来凑够表数量。

## 4. 高校与学生范围

### 4.1 多高校逻辑隔离

- 平台未来支持多所学校。
- 每名用户归属于一所学校。
- 用户只能浏览和参与自己学校的物品、回收点、公益项目与交接。
- 不允许跨校交易、跨校借用或跨校公益领取。
- 首版提供预置学校数据或导入样本，后续再接入全国高校库。
- 全国高校认证目前为模拟或人工导入，不接真实政府、教育主管部门或学校认证接口。

### 4.2 学校与校区

- 一所学校可以有一个或多个校区。
- 只有单校区的高校也必须能够正常使用。
- 同一所学校的不同校区之间允许物品流转。
- 禁止跨学校流转；任何业务数据都必须受所属高校范围限制。

## 5. 角色与权限

首版有三类可见业务角色，并保留一个校级管理员登录身份：

1. 在校学生。
2. 公益管理员（回收）。
3. 平台管理员。
4. 校级管理员（预留）：账号可导入，管理功能暂不开放。

物品所有者、借用者、购买者和领取者都属于在校学生，通过具体业务关系获得不同操作权限，不单独创建“出借人”或“买家”角色。

角色标签显示在用户头像下方，使用边框颜色区分，不是头像框：

- 学生：蓝色框。
- 公益管理员（回收）：橙黄色框。
- 平台管理员：红色框。

## 6. 注册与登录

### 6.1 学生账号

学生注册字段：

- 学号。
- 手机号。
- 密码。

注册前置条件：

- 平台管理员已经导入所在学校的学生名单。

学生名单字段：

- 学生姓名。
- 电话号码。
- 学号。
- 年级。
- 班级。
- 专业。
- 所属学院。
- 所属学校与校区。

注册核验：

- 学号与手机号必须匹配已导入名单，防止冒领。
- 手机号不匹配时提示：“电话号码有误，可能不是学生本人预留的电话号码。如有错误请联系辅导员进行信息更改。”
- 对空值、格式错误、学号不存在、手机号不匹配、重复注册等情况进行防呆提示。

### 6.2 管理账号

- 公益管理员（回收）和校级管理员账号由平台管理员统一导入或创建。
- 平台管理员账号通过受控方式预设，首版只预置 1 个；这不是系统账号数量上限。
- 除在校学生外，不开放自主注册。

### 6.3 登录方式

登录先选择四类身份：在校学生、公益管理员（回收）、平台管理员、校级管理员（预留）。在校学生随后选择学校和校区，再进入学生登录页。

学生支持两种登录：

1. 手机号或学号 + 密码。
2. 图片验证码 + 模拟手机号短信验证码。

验证码规则：

- 先通过图片验证码，再请求手机验证码。
- 手机验证码 60 秒内有效。
- 不接真实运营商短信接口。
- 开发环境显示测试验证码或写入可验证的模拟消息；不得让前端自行决定验证码结果。
- 未注册账号提示“登录”还是“注册”的明确入口。

### 6.4 个人资料

- 支持修改昵称。
- 支持修改头像。
- 头像与物品图片在技术可行时进入首版。
- Cloudflare 部署时文件存储需使用 R2 或等价对象存储，不能依赖 Worker 本地磁盘。

## 7. 页面与设备

- 桌面浏览器为主要验收环境。
- 做基础响应式适配，保证手机浏览器可完成核心流程。
- 不开发原生 App。
- 不开发微信小程序。

## 8. 模拟与真实边界

以下能力首版全部模拟：

- 二手交易支付。
- 支付成功、取消和退款状态。
- 手机短信验证码。
- 手机号验证结果。
- 全国高校认证。
- 公益义卖和公益金。

以下能力首版真实执行于本地数据库：

- 学生名单匹配与注册校验。
- 学校范围隔离。
- 物品状态流转。
- 交接码验证。
- 状态历史与操作记录。
- 公益实物募集数量和回执公示。

公益首版不接收真实资金，不宣称已经真实帮助特定儿童。真实实物捐赠需由合作组织线下核验并给出回执。

## 10. Cloudflare 目标

- 课程验收以本地 Flask + PostgreSQL 运行为主。
- 用户希望额外完成 Cloudflare 部署。
- Cloudflare 部署不作为阻断课程交付的唯一条件。
- 优先公网方案为 Vercel + Neon PostgreSQL + R2 或 Vercel Blob。
- 若采用 Cloudflare，需要补充 Hyperdrive、Neon/Supabase、R2、Node/uv/pywrangler 工具链和部署配置。
