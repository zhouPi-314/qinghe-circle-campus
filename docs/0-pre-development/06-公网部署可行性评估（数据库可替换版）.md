# 青禾流转公网部署可行性评估（数据库可替换版）

| 项目 | 内容 |
|---|---|
| 文档编号 | PRE-06 |
| 文档版本 | 1.0 |
| 状态 | 待批准 |
| 评估日期 | 2026-11-19 |
| 前提变化 | 课程不再要求必须使用 MySQL，可使用 PostgreSQL 或其他合适数据库 |
| 应用约束 | Flask、Jinja2、Web 端、单人、4 周、免费额度优先 |

## 1. 修正后的结论

数据库限制解除后，Supabase 成为可用方案，但不再是首选。

推荐顺序：

1. **总体首选：Vercel + Neon PostgreSQL + Cloudflare R2 或 Vercel Blob**
2. **Cloudflare 一体化：Cloudflare Workers + Hyperdrive + Neon/Supabase + R2**
3. **全平台一体化：Vercel + Supabase PostgreSQL + R2**
4. **只求最少平台：Vercel + Neon + Vercel Blob**
5. **不推荐：Cloudflare + Supabase + Vercel 全部叠在一起**
6. **不推荐首版使用 Cloudflare D1**：需要把 SQLAlchemy/数据库访问改写成 D1 绑定路径，课程收益低

若目标是“免费、稳定、部署简单、保留 Flask/Jinja2”，选择：

```text
Vercel
  + Neon PostgreSQL
  + Cloudflare R2（或 Vercel Blob）
```

若目标是“应用也必须运行在 Cloudflare”，选择：

```text
Cloudflare Workers
  + Hyperdrive
  + Neon 或 Supabase PostgreSQL
  + R2
```

## 2. 数据库选择

| 数据库 | 免费额度 | 是否闲置暂停 | 与 Cloudflare Hyperdrive 官方兼容 | 适用判断 |
|---|---|---|---|---|
| Neon PostgreSQL | 100 个项目；每项目每月 100 CU-hours、1 GB 存储、5 GB 公网流量；无需信用卡 | 不暂停项目；计算空闲 5 分钟后缩到零，下次查询自动唤醒 | 是，官方有 Neon 连接示例 | 首选；课程数据量远低于 1 GB |
| Supabase PostgreSQL | 500 MB 数据库、1 GB 文件存储、5 GB egress；2 个活跃项目 | 项目连续 1 周无活动后暂停 | 是，官方有 Supabase 连接示例 | 可用；若同时需要 Supabase Auth/Storage 更方便 |
| TiDB Cloud Starter | MySQL-compatible；每月 5 GiB 行存、5000 万 RU；无需信用卡 | 官方未按“项目暂停”描述 | MySQL 协议兼容，但未列入专项 Provider | 只有在仍想保留类 MySQL 写法时选择 |
| Cloudflare D1 | SQLite；有免费读写额度 | 无传统项目暂停 | Cloudflare 原生 | 不建议首版：数据库绑定、SQL 方言和本地/线上双实现增加改造量 |
| 本地 MySQL | 0 元 | 本机关机即不可用 | 不可直接公网访问 | 只用于课程本地验收，不作为公网数据库 |

## 3. 平台组合比较

### 3.1 Vercel + Neon + R2

```text
浏览器
  → Vercel Flask/WSGI
  → Neon PostgreSQL
  → Cloudflare R2
```

优点：

- Vercel 官方支持 Flask、Django、FastAPI 的 WSGI/ASGI 部署。
- Neon 免费层不要求信用卡，不暂停项目，1 GB 数据库对课程足够。
- Cloudflare 官方支持 Hyperdrive 连接 Neon，未来可平滑切换到 Cloudflare Workers。
- R2 免费层为每月 10 GB 存储、100 万 Class A、1000 万 Class B，公网出口免费。
- 不改变 Flask + Jinja2 架构。

风险：

- Vercel 单函数最长 300s，普通请求足够，但长任务不适合。
- Vercel Function 请求/响应体约 4.5 MB，图片需压缩或走 Blob/R2 直传。
- Vercel 默认单区域，可能有跨区域延迟。
- PostgreSQL 需要修改 SQLAlchemy URL、驱动和少量 SQL 方言。

适用结论：

- 当前最稳的公网展示路线。
- 课程本地可用 SQLite 或 PostgreSQL 做适配；公网直接使用 Neon。

### 3.2 Vercel + Neon + Vercel Blob

```text
浏览器
  → Vercel Flask/WSGI
  → Neon PostgreSQL
  → Vercel Blob
```

优点：

- 只需 Vercel + Neon 两个平台。
- Vercel Blob 有 1 GB 存储、前 10,000 Simple Operations、2,000 Advanced Operations、10 GB Data Transfer 免费额度。
- Python SDK 可直接使用，不需要额外配置 S3 客户端。

风险：

- 1 GB 文件容量比 R2 的 10 GB 小。
- Blob 操作、上传和访问会消耗 Vercel 共享额度。
- 课程项目如果把图片压到 1 MB 以下，1 GB 足够。

适用结论：

- 如果“平台数量少”比“图片容量大”更重要，这是最省配置的方案。

### 3.3 Cloudflare Workers + Hyperdrive + Neon/Supabase + R2

```text
浏览器
  → Cloudflare Workers（Flask/WSGI）
  → Hyperdrive
  → Neon 或 Supabase PostgreSQL
  → R2
```

优点：

- 应用、数据库连接池、对象存储和 CDN 全在 Cloudflare。
- Cloudflare 官方分别提供 Neon、Supabase 的 Hyperdrive 集成说明。
- Workers Free 每天 100,000 请求，Hyperdrive Free 每天 100,000 次数据库操作。
- R2 免费容量和出口流量适合图片。

风险：

- Workers Free 每请求只有 10 ms CPU，鉴权和 SSR 可能达到 10–20 ms。
- Python Workers + Flask + Hyperdrive + PostgreSQL 组合复杂。
- 需要 `uv`、Wrangler、兼容日期和连接池配置。
- 失败后可能需要 Workers Paid，成本与排错时间增加。

适用结论：

- 适合作为第二阶段部署目标。
- 不建议在本地 Flask 验收前投入大量时间。

### 3.4 Vercel + Supabase + R2

优点：

- Supabase 数据库、Auth、Storage 一体化。
- Vercel 对 Flask 支持好。
- Cloudflare R2 比 Supabase 免费存储更大。

风险：

- 本项目已有自定义学生名单核验、模拟短信、三级角色和学校隔离，Supabase Auth 复用价值有限。
- 免费项目闲置 1 周后暂停，公网演示可能被自动暂停。
- 500 MB 数据库对课程足够，但没有明显的 Neon 优势。

适用结论：

- 如果后续想减少自建认证和文件接口，可考虑。
- 当前不优先。

### 3.5 Cloudflare + Supabase + Vercel 三平台叠加

不推荐：

- Vercel、Cloudflare 和 Supabase 都有独立部署、密钥和日志体系。
- 同一请求可能跨 Vercel 应用、Cloudflare 数据库代理、Supabase 数据库，排错成本高。
- 对单人 4 周项目没有任何必要。

## 4. 数据库切换对项目代码的影响

当前项目尚未建表，因此现在切换 PostgreSQL 的成本最低。

需要调整：

- 驱动：`PyMySQL` 改为 `psycopg` 或 `psycopg2`。
- SQLAlchemy URL：改为 `postgresql+psycopg://...`。
- 主键：MySQL `AUTO_INCREMENT` 改为 PostgreSQL Identity/Serial。
- 布尔、时间、JSON 字段使用 SQLAlchemy 类型，避免数据库方言硬编码。
- `ON UPDATE CURRENT_TIMESTAMP` 等 MySQL 特性改为应用层或触发器。
- 字符排序、大小写和索引名称在 PostgreSQL 中重新验证。
- 如果同一套代码同时支持本地 SQLite/PostgreSQL，需要避免数据库专属 SQL。

业务规则、角色、状态机、表单和模板不需要因数据库替换而重写。

## 5. 文件存储选择

| 方案 | 免费额度 | 优点 | 风险 |
|---|---|---|---|
| Cloudflare R2 | 10 GB-month；1M Class A；10M Class B；出口免费 | 容量大，适合物品图片和头像 | 需要创建 R2 存储桶、S3 凭据和签名逻辑；开通时可能要求结算信息 |
| Vercel Blob | 1 GB；前 10,000 Simple、2,000 Advanced、10 GB Data Transfer | 与 Vercel 项目集成最省事，有 Python SDK | 容量较小；上传和读取计入 Vercel 共享免费额度 |
| Supabase Storage | 1 GB | 与 Supabase DB 集成 | 若不用 Supabase，则新增平台；免费项目会暂停 |

首版建议：

- 图片压缩到 1 MB 以下。
- 采用 Vercel Blob 可减少一套云平台；
- 若已有 Cloudflare R2 并愿意配置 S3 凭据，R2 容量更充足。

## 6. 成本判断

在课程演示流量下，以下组合都可以保持 0 美元：

- Vercel Hobby + Neon Free + Vercel Blob Free
- Vercel Hobby + Neon Free + R2 Free
- Cloudflare Workers Free + Hyperdrive Free + Neon Free + R2 Free

但必须注意：

- 免费额度按平台规则执行，功能会受限。
- Vercel 函数有 4.5 MB 请求/响应限制。
- Cloudflare Workers Free 的 10 ms CPU 可能不够复杂 SSR。
- Vercel Blob 只有 1 GB。
- Supabase 免费项目会因 1 周无活动暂停。
- 任何付费升级前都要确认是否绑定支付方式。

## 7. 推荐决策

### 方案 A：最省事

```text
Vercel + Neon + Vercel Blob
```

适合：

- 只做课程和作品展示。
- 图片总量小于 1 GB。
- 不想维护 Cloudflare Worker 入口。

### 方案 B：最平衡

```text
Vercel + Neon + Cloudflare R2
```

适合：

- 需要更多图片空间。
- 希望保留 Cloudflare 作为对象存储和 CDN 基础设施。
- 愿意配置 R2 凭据和上传签名。

### 方案 C：Cloudflare 优先

```text
Cloudflare Workers + Hyperdrive + Neon/Supabase + R2
```

适合：

- 必须让应用本身运行在 Cloudflare。
- 能接受 Python Worker 和免费 CPU 风险的调试成本。

## 8. 建议落地顺序

1. 本地完成 Flask + PostgreSQL 适配，数据表按 PostgreSQL 建。
2. 创建 Neon Free 项目并导入种子数据。
3. 部署 Vercel Flask 应用到公网。
4. 选择 Vercel Blob 或 R2 接入头像和物品图片。
5. 验证多高校隔离、学生名单认证和四类流转。
6. 剩余时间再做 Cloudflare Workers + Hyperdrive PoC。
