## 1. 计划目的

本计划用于规定项目从批准到交付的组织方式、阶段顺序、里程碑、文档产物、质量要求和风险控制。

计划开始日期为 2026-11-18，目标截止日期为 2026-12-16。项目按 21 个工作日编排，周末原则上不使用；若实际执行进度落后，优先削减增强功能，不以压缩测试和交付检查为代价。

## 2. 项目策略

### 2.1 总体原则

1. 先定义问题和边界，再分析需求，最后设计代码。
2. 每阶段都必须有可检查文档，不能以聊天记录代替正式产物。
3. 每个开发增量结束时必须有可运行版本。
4. 首版范围冻结后，新增功能只进入变更清单。
5. 优先完成一条完整业务链，不平均分配时间给所有页面。
6. 不引入真实支付、短信、物流、实名认证和真实公益资金。

### 2.2 开发方法

采用轻量瀑布加迭代增量：

- 问题定义、可行性、计划作为前置门禁。
- 6.1 需求分析和 6.2 概要设计完成并通过审核后，才进入编码。
- 6.3 开发拆成若干可运行增量。
- 测试与增量同步进行，最终再进行系统回归。

该方式比全量瀑布更适应单人项目，也能保留项目要求的设计先行特征。

## 3. 基准假设

1. 开发人员为单人。
2. 每天有效投入 5–7 小时。
3. 总周期为 21 个工作日。
4. 技术主线为 Flask、PostgreSQL 18、Flask-SQLAlchemy 和 Jinja2；公网数据库优先 Neon PostgreSQL。
5. 首版主要面向桌面浏览器，并保证基础移动网页可用。
6. 真实外部接口为零或仅保留可替换的模拟边界。
7. 项目验收以本地运行为主；Cloudflare 部署为目标增强项，不阻塞项目验收。
8. 业务表总数不在 6.1 确定；6.2 概念数据模型完成后确认，不预设 29 张或固定数量，也不通过拆表凑数。
9. 支持多高校逻辑隔离，但用户只能在本校范围内使用。
10. 首版四类物品流转全部可操作。
11. 使用在校学生、公益管理员、平台管理员三类业务角色，并提供校级管理员登录身份。
12. 登录、学生名单核验、图片验证码和手机验证码均可在本地模拟。
13. 图片上传在核心业务流程完成后实现；Cloudflare 部署时改用 R2 或预置图片。
14. 文档使用 Markdown，并按阶段进入独立文件夹。

## 9. 质量计划

### 9.1 文档质量

- 每个阶段文档包含版本、日期、状态和变更记录。
- 业务规则与异常场景不能只写正常流程。
- 图表与正文使用同一术语。
- 需求设想必须经过人工删减，不能直接作为最终需求。

### 9.2 代码质量

- 路由、业务处理和数据模型职责分离。
- 不同业务模块通过清晰入口协作，减少跨模块直接依赖。
- 关键状态变更使用事务。
- 输入校验、权限校验和对象归属校验不依赖前端。
- 不提前编写没有业务入口的“未来模块”。

### 9.3 测试质量

至少覆盖：

- 未登录访问。
- 角色越权。
- 物品状态冲突。
- 借用逾期与归还。
- 取消、拒绝和异常交接。
- 公益项目进度不能超过有效募集数量。
- 回执公示权限。
- 重复提交和非法状态跳转。

### 9.4 缺陷处理

缺陷分为：

- P0：无法启动、数据损坏、严重越权。
- P1：核心流程不可完成。
- P2：一般功能错误或明显体验问题。
- P3：文本、样式或低影响问题。

P0、P1 必须在交付前关闭；P2 至少记录处理结论；P3 可进入已知限制。

## 10. 配置与版本管理

1. 使用 Git 管理代码和文档。
2. 每完成一个可运行增量创建一个可识别提交。
3. 提交信息说明业务结果，不使用“最终版”“修改一下”等笼统描述。
4. `.env`、数据库密码和部署密钥加入忽略规则。
5. 在 GitHub 提交前检查历史记录中的敏感信息。
6. 公共仓库提供 `.env.example`、初始化 SQL 和虚构演示数据。

## 11. 变更控制

首版范围冻结后：

1. 新功能先写入变更清单。
2. 评估是否影响 6.1、6.2、数据库或测试。
3. 只有同时满足“项目必需、可在一日内完成、不破坏主流程”才进入当前版本。
4. 其他功能进入 Roadmap，不通过占位按钮提前展示。

优先拒绝以下变更：

- 真实支付和资金托管。
- 短信和实名认证。
- 实时聊天。
- 地图和物流。
- 推荐算法。
- 公益义卖真实收款。
- 为“企业感”增加无业务需求的消息队列、微服务或复杂抽象。

## 12. 风险与应急预案

| 风险事件 | 触发信号 | 应急方案 |
|---|---|---|
| 第 8 天仍无一条完整业务链 | 只有页面和 CRUD | 暂停扩展其他模式，集中完成共享借还闭环 |
| 四类流转状态冲突 | 同一物品存在多个进行中业务 | 立即冻结相关功能，回到 6.2 修正状态边界 |
| 公益功能膨胀 | 开始讨论真实收款和采购 | 保留实物捐赠与回执，公益义卖移出首版 |
| Cloudflare 阻塞超过 4 小时 | 驱动、连接或 CPU 限制无法解决 | 停止部署排查，改回本地演示 |
| 公网 PostgreSQL 连接失败 | Vercel 或 Hyperdrive 无法稳定连接 Neon | 先测试 Neon 连接池和 SSL，失败后切换 Supabase |
| 文档明显落后 | 代码已完成但无阶段记录 | 暂停新增代码，补齐当前增量文档 |
| 临近截止 | 核心流程仍有 P1 缺陷 | 缩减非核心页面，优先修复主流程和可复现性 |
